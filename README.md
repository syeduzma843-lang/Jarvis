# JARVIS Assistant — Phase 0/1 Scaffold

A working starting point: FastAPI agent backend (memory + tool-calling +
swappable LLMs + voice) and a native Android client that connects to it.
See `docs/ARCHITECTURE.md` for the full design rationale.

## What actually runs right now

- Text chat with memory + tool-calling: `POST /api/chat`
- Real-time voice over WebSocket: `/ws/voice` (needs Deepgram + ElevenLabs keys)
- Android app that connects to the voice endpoint, streams mic audio, plays
  back the response

## Run the backend

```bash
cd backend
cp .env.example .env
# edit .env: at minimum set ANTHROPIC_API_KEY (or OPENAI_API_KEY / GOOGLE_API_KEY)
docker compose up --build
```

Test the brain without any voice/mobile setup:

```bash
curl -X POST http://localhost:8000/api/chat \
  -H "Content-Type: application/json" \
  -d '{"user_id": "dev-user-1", "message": "What is 42 * 17, and remember I prefer metric units"}'
```

That single call exercises: Postgres short-term memory, ChromaDB long-term
memory, the tool registry (calculator tool fires), and the LLM router.

## Get a ready-made .apk with zero coding (GitHub Actions)

This repo includes `.github/workflows/build-android.yml`, which builds the
APK in the cloud and hands you a download link. No Android Studio, no
terminal commands, no code to write.

1. Create a free GitHub account if you don't have one: https://github.com/signup
2. Create a new repository: click **+** (top right) → **New repository** →
   name it anything (e.g. `jarvis-assistant`) → **Create repository**.
3. On the new repo's page, click **uploading an existing file** (or drag the
   whole unzipped `jarvis-ai-assistant` folder onto the page).
4. Commit the upload (the green "Commit changes" button).
5. Click the **Actions** tab at the top of the repo. You'll see "Build
   Android APK" running automatically (it triggers on upload). If it's not
   running, click it → **Run workflow** → **Run workflow** (green button).
6. Wait ~3-5 minutes for the green checkmark.
7. Click the finished run → scroll to **Artifacts** → download
   **jarvis-debug-apk**. That's a zip containing `app-debug.apk`.
8. Transfer that `.apk` to your Android phone (email it to yourself, Google
   Drive, USB cable — any way you'd move a file) and tap it to install.
   You'll need to allow "install from unknown sources" the first time
   Android asks.

Note: this debug APK talks to `ws://10.0.2.2:8000`, which only exists on an
emulator — it won't reach anything from a real phone yet. Once you have a
backend deployed somewhere reachable (Phase 10, cloud deployment), update
`BACKEND_WS_URL` in `JarvisApplication.kt` to that address, re-commit, and
Actions will rebuild automatically. Until then, the "no-coding" APK is real
and installs fine — it just needs a reachable backend to actually talk to.

## Deploy the backend so the app works from a real phone (not just an emulator)

The Android app can't reach `10.0.2.2` from outside an emulator — it needs a
real, public backend URL. This repo includes `render.yaml` (a Render
"Blueprint"), which deploys the backend + a managed Postgres database
together, no manual server setup.

**Before you start:** verify current pricing/free-tier terms at
render.com/pricing — they change, and conflicting info circulates online.
Regardless of free-tier availability, avoid a spin-down free instance for
this project specifically: the 30-60s cold start it introduces defeats the
"low latency voice assistant" goal. A cheap always-on tier is the right
choice here.

1. Push this repo to GitHub if you haven't already (see the APK section
   above for the no-terminal upload method).
2. Go to https://dashboard.render.com → **New** → **Blueprint** → connect
   your GitHub repo. Render reads `render.yaml` automatically and shows you
   the two resources it'll create (`jarvis-backend` web service +
   `jarvis-db` Postgres).
3. Click **Apply**. Render will prompt you for the env vars marked
   `sync: false` in `render.yaml` — paste in your actual keys:
   - `ANTHROPIC_API_KEY` (console.anthropic.com)
   - `DEEPGRAM_API_KEY` (console.deepgram.com)
   - `ELEVENLABS_API_KEY` (elevenlabs.io)
   - `WEB_SEARCH_API_KEY` (tavily.com, optional — search tool just won't
     work without it)
   `BACKEND_API_KEY` and `JWT_SECRET` are auto-generated by Render — you
   don't need to supply those.
4. Wait for the deploy to go green, then note your service URL, e.g.
   `jarvis-backend-xyz1.onrender.com` (Render dashboard → your service →
   top of page).
5. Copy the auto-generated `BACKEND_API_KEY` value: Render dashboard →
   `jarvis-backend` → **Environment** tab → click to reveal.
6. In GitHub, open `android/app/src/main/java/com/jarvis/assistant/JarvisApplication.kt`
   in the web editor (pencil icon), replace `YOUR-APP-NAME.onrender.com`
   with your real Render URL (`wss://`, not `ws://` — Render terminates TLS
   for you) and `YOUR-BACKEND-API-KEY-FROM-RENDER` with the key from step 5.
   Commit directly to `main`.
7. GitHub Actions rebuilds the APK automatically. Download the new
   `jarvis-debug-apk` artifact from the Actions tab, install it on your
   phone — it now talks to your real, always-on backend from anywhere with
   internet, not just an emulator.

**Known limitation to flag honestly:** long-term memory (ChromaDB) writes to
local disk, which Render wipes on redeploy unless you attach a persistent
Disk (the commented-out block in `render.yaml` — needs a paid instance
type). Short-term memory and preferences (Postgres) persist normally either
way.

## Run the Android app (for building/customizing it yourself)

1. Open `android/` in Android Studio (Iguana or later).
2. If using an emulator, the default `BACKEND_WS_URL` in
   `JarvisApplication.kt` (`ws://10.0.2.2:8000/...`) already points at your
   host machine's localhost — no changes needed.
3. If using a physical device, run `adb reverse tcp:8000 tcp:8000`, or change
   `BACKEND_WS_URL` to your machine's LAN IP.
4. Run the app, tap "Talk to Jarvis", grant mic permission, speak. Transcript,
   reply text, and spoken audio (streamed as raw PCM — no decode step needed)
   should all work end to end.
